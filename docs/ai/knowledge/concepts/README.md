# concepts/

Focused explanations of **durable concepts** used across the codebase — core types, key
abstractions, domain ideas. One concept per file.

A good concept page:

- leads with one or two sentences on what it is and why it matters,
- explains how it works with concrete detail from the actual code (real names, real paths),
- calls out common misuse / anti-patterns if there are any,
- ends with **Related links** (code, conventions, ADRs, other knowledge pages).

Create a page here when the concept will recur across sessions and is awkward to explain
inline each time. See [`../index.md`](../index.md) for the full page-creation rules, and add
your new page to the index and to [`../log.md`](../log.md).
