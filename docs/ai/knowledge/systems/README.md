# systems/

Descriptions of **major subsystems** and how they interact — the processing pipeline, the
config layer, the API surface, the storage layer, and so on. One subsystem per file.

A good system page:

- states what the subsystem does and where it lives in the code,
- walks the main flow (stages, key classes/modules, entry points),
- names the design patterns it relies on and links to their conventions,
- ends with **Related links** to architecture, conventions, and relevant concept pages.

This sits one level below [`../../architecture.md`](../../architecture.md): architecture is the
map; a system page is the detailed tour of one region. Add new pages to
[`../index.md`](../index.md) and [`../log.md`](../log.md).
